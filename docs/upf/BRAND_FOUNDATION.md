# UPF-Insight — Brand Foundation

> **Document kind:** brand/product identity.
> **Date:** 2026-08-14 · **Version:** v0.1.0

---

## 1. Brand essence

**Power-intent intelligence for digital design.** UPF-Insight brings order to
power intent before power-aware implementation — the way Ṛta brings order to
timing intent before STA.

| Element | Value |
|---|---|
| Tagline | *Bring order to power intent before power-aware implementation.* |
| Promise | Deterministic · Evidence-backed · Local-first · Reproducible |
| Family | The Ṛta constraint-intelligence family (sdc-tools → UPF-Insight) |
| Category | Power-intent validation & analysis (IEEE 1801 / UPF) |

## 2. Positioning statement

For PD, low-power, and verification engineers who own UPF power intent,
UPF-Insight is a deterministic validation and analysis tool that finds
power-intent defects — unsafe domain crossings, incoherent power states,
missing isolation — before expensive power-aware implementation, unlike
generic editors or ad-hoc scripts, because it analyzes power intent as a
*system* with an honest support boundary and per-finding evidence.

## 3. Name rationale

- **UPF** — the format (IEEE 1801).
- **Insight** — the tool's output: understanding of the power-intent system,
  not just a list of text complaints.

Aliases: `upf-insight` (primary CLI), `upfi` (short alias).

## 4. What the brand stands for

- **Honesty** — "no errors ≠ power proven correct." The support boundary is
  always disclosed.
- **Determinism** — same input, same output, every machine, no LLM in the
  engine.
- **Locality** — analysis runs on your machine; nothing leaves it.
- **Evidence** — every finding traces to a file:line.
- **Open core** — community MIT; enterprise layers additive, never degrading.

## 5. What the brand is NOT

- Not "AI-powered" (no LLM in the analysis path).
- Not a power/IR or STA signoff tool.
- Not a cloud service.
- Not a generic EDA platform.

## 6. Voice

- Concise, engineering-first, confident but honest.
- Explains the boundary of every claim (READY ≠ signoff).
- Uses precise terminology from the IEEE 1801 world.

## 7. Visual identity direction

The sibling Ṛta project uses a clean, technical, open-source aesthetic.
UPF-Insight inherits: monospace code blocks, tables for rule catalogs, and a
strong "boundary" visual metaphor (what is validated vs not) in reports and
the workspace. No vendor-locked branding.
