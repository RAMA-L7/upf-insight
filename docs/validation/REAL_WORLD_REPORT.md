dialect, not the standard.**

## Why this was not caught

The 42-mutation corpus in `engine/quality.py` detects **42/42** seeded defects
(100%). Every seeded mutation is written by the same author as the parser, in
the same dialect. A parser and its own test fixtures agree by construction.

Detection rate measures *recall against injected defects*. It says nothing
about *precision on foreign input*. This corpus measures the second thing.

## Validation environment

The laptop has **no commercial or open-source EDA tools installed** — no
Yosys, OpenSTA, OpenROAD, Magic, Icarus, Verilator, Liberty/LEF libraries, or
Docker. `tcl-magic` (0.0.5) is present as a Python package only.

Consequence: **no tool-to-tool differential testing was possible.** Every
verdict below rests on the IEEE 1801 grammar, not on agreement with a
reference implementation. Where the standard admits both spellings, that is
stated explicitly rather than guessed.

## Defects found

### D1 — Grammar rejects 9 legal IEEE 1801 options (38 FP, 52% of all FPs)

`_LEGAL_OPTIONS` in `model/builder.py` is narrower than the standard. These
are all legal and all reported as `UPF-002 Illegal option` **at severity
error**:

| Command | Rejected option | IEEE 1801 |
|---|---|---|
| `create_power_domain` | `-include_scope` | standard |
| `create_power_switch` | `-domain`, `-input_supply`, `-output_supply` | standard (2.1/3.0 spelling) |
| `set_isolation` | `-isolation_power_net`, `-isolation_ground_net` | standard |
| `set_isolation_control` | `-location` | standard |
| `set_retention` | `-retention_power_net`, `-retention_ground_net` | standard |

The engine only accepts the UPF 3.1+ `-input_supply_port` /
`-output_supply_port` spelling for `create_power_switch`. Real files
predominantly use the 2.1 form.

**Impact is structural, not cosmetic.** Because `-input_supply` /
`-output_supply` are dropped, every switch parses with
`input_supply: null, output_supply: null` — disconnected from its supplies.
That single failure cascades into `UPF-076` ("switch declares an on-state but
no off-state — the domain can never power down"), which is **factually wrong**
about the design: the file does define an off-state; the parser discarded the
options that would have told it so.

### D2 — `map_power_switch` unsupported (4 FP)

A standard command absent from `_SUPPORTED`, reported as `UPF-001 Unknown UPF
command` at severity **error**. Note the sibling `map_isolation_cell` /
`map_level_shifter_cell` / `map_retention_cell` *are* supported — the power
switch was simply missed.

### D3 — Brace groups not split in `connect_supply_net` (8 FP)

`connect_supply_net vdd_top_net -ports { VDD_TOP }` is ordinary Tcl. The
handler stores the raw token:

```
connected_to = ['{ VDD_TOP }']      # instead of ['VDD_TOP']
```

`UPF-024` then reports "connected to unknown target `{ VDD_TOP }`". Every
brace-group port reference in real UPF triggers this.

### D4 — Genuine findings (19 on shipped corpus, 42 including external run)

These are real and useful — the tool is not merely noisy:

- **UPF-044** — `-applies_to outputs` does not cover bidirectional crossings.
  This is *Hall of Shame bug #2* in industry low-power checklists (missing LS
  on a feedback path).
- **UPF-047 / UPF-051 / UPF-071** — isolation / retention / power-switch
  control signals not confirmed always-on. *Hall of Shame bug #1* (enable
  powers down with the domain it isolates).
- **UPF-087** — `top/sram/reg*` retention wildcard flagged HIGH risk.
- **UPF-036** — strategies present with no PST to condition them.

This is the signal the tool exists to produce, and it is working.

## Honest assessment

**What works.** The semantic layer is genuinely valuable. Isolation
coverage, always-on control-signal confirmation, level-shifter necessity,
wildcard risk, and PST conditioning are exactly the checks that catch silicon
bugs, and they fire correctly on real files.

**What does not work.** The front end cannot read real-world UPF. A user
running this on their own file today would receive ~12 errors, essentially all
spurious, and — critically — `BLOCKED` readiness with real findings buried
underneath. **This is worse than useless in CI**: a gate that fails for
phantom reasons gets disabled, and then it protects nothing.

**Confidence.** High on D1–D3 (verified by execution against the standard's
grammar and reproduced on an independently authored file). Medium on severity
calibration, which was not tested because no reference tool exists here.

## Required improvements, in priority order

**P0 — grammar coverage.** Accept the 9 legal options and model them. This is
the single highest-leverage change: it removes 38 of 53 false positives and
un-breaks switch modeling, which also clears the D1 cascade.

**P0 — brace-group expansion.** Split `{ a b c }` into members for
`-ports`/`-nets`/`-elements`. Tcl requires it; real files use it constantly.

**P1 — `map_power_switch`.** Add to `_SUPPORTED` with the same shape as the
existing `map_*_cell` handlers.

**P1 — `UPF-002` severity.** An option the engine has not implemented is
`UNSUPPORTED` support, not `VALIDATED`. Tagging a known-unimplemented option
as `VALIDATED` is exactly the over-claim `CLAUDE.md` forbids. Suggested:
`severity="warning"`, `support="UNSUPPORTED"` until the option is modeled.

**P2 — `UPF-001` severity.** Unknown-command is right at *error* for genuinely
unknown commands, but a command the standard defines and the engine lacks
should be `warning` + `UNSUPPORTED`, not an error.

**P2 — differential testing.** Install OpenSTA/Yosys + a UPF parser (or a
reference `check_power_intent`) to settle severity calibration by comparison
rather than by reasoning.

**P3 — conformance corpus.** Widen `tests/corpus/` beyond these three files
toward public IEEE 1801 examples, and gate CI on the FP-rate from
`scripts/validate_corpus.py` so this cannot regress silently.

## Reproducing this report

```bash
python scripts/validate_corpus.py          # table + buckets
python scripts/validate_corpus.py --json   # machine-readable
python scripts/validate_corpus.py path.upf # explicit files
```

The harness classifies each finding by root cause and prints any
`unclassified` bucket, so a new failure mode surfaces rather than being
counted as genuine.
