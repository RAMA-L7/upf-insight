Six deterministic capabilities on one engine. No EDA license, no cloud round-trip, no probabilistic output. What it reports, it can prove.

check — validate

74 rules across seven layers: SYNTAX, REFERENCE, SUPPLY_DOMAIN, PST, STRATEGY, DESIGN and hierarchy promotion. Severity-ranked findings, each anchored to a file and line number.

▤

model — object graph

Dump the parsed power-intent model as JSON: domains, supply sets, strategies, switches, PSTs. A clean intermediate form for your own tooling and reviews.

▦

pst — state analysis

Reachability over the Power State Table: impossible states, empty or duplicated rows, undeclared transitions, isolation/level-shifter gaps at domain crossings.

⇄

diff — semantic compare

Two UPF revisions in, a structural verdict out. Added/dropped domains, rewired supplies, changed clamp values — model-level truth instead of textual churn.

◎

coverage — what's missing

Structural domain/supply coverage shows which parts of your power architecture the UPF never describes. Gaps become explicit work items, not silent assumptions.

✦

generate — scaffold UPF

Standards-correct skeletons for new designs: pick your power domains, always-on blocks and retention needs; get a well-formed starting file in seconds.

Built for pipelines

CI gates & baselines

Save a baseline of known findings, then gate future runs against policy: BLOCKERS_ONLY, NO_READINESS_REGRESSION or STRICT. The exit-code contract (0 pass · 1 gate failed · 2 invalid invocation · 3 engine failure) drops into any CI system without glue code. JUnit XML included.

Trust boundary

Every answer says how sure it is

VALIDATED

The finding is backed by the full command stream and model. Deterministic — rerun it anywhere, get the same result.

PARTIAL

Some inputs were unavailable (e.g. design netlist context). The rule ran with reduced evidence and says so explicitly.

UNSUPPORTED

Constructs outside the supported UPF subset are reported as unsupported — never silently ignored. Honest support boundaries, always.
